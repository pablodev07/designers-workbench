<div className="read-me documentation">
  <h2>Getting Started</h2>

  <h3 id="setup">Setup and Run</h3>

  <p>Ensure you have Node 20 installed (the project includes an .nvmrc):</p>
</div>

```bash
nvm use
npm install
```

<div className="read-me documentation">
  <p>Run either entry point:</p>
</div>

```bash
npm run storybook   # Component catalog on http://localhost:6006
npm run dev         # App shell on http://localhost:3000
```

<div className="read-me documentation">
  <p>Both use the same Vite config and share src/modules/. They are independent processes.</p>

  <h3 id="themes">Theme Switcher</h3>

  <img src="/images/read-me/themeswitcher.png" alt="Theme switcher" style={{ width: '350px', height: '50px' }} />

  <p>Use the <strong>Theme</strong> toolbar button to switch between design systems:</p>

  <div className="block">
    <p><strong>SLDS2 - Cosmos</strong> — Salesforce Design System 2 (default). Uses slds2.cosmos.css with all --slds-r-* and --slds-g-* custom properties.</p>
    <p><strong>SLDS1 - Lightning Blue</strong> — Classic SLDS. Uses salesforce-lightning-design-system.min.css.</p>
    <p><strong>WES for EC</strong> — Web Experience Standard for Experience Cloud. Wraps components in .wes-page .wes-style .wes-theme classes.</p>
  </div>

  <p>Components adapt to all three themes — never hard-code colors, fonts, or spacing. Use SLDS tokens and styling hooks exclusively, enforced with Claude instructions.</p>

  <h3 id="create">Creating Components</h3>

  <p>Component creation is handled by <strong>Claude Code</strong>. When you ask Claude to create a component inside this project, it automatically:</p>

  <div className="steps-grid">
    <div className="step-card">
      <span className="step-pill"><img src="/images/read-me/scaffold.png" alt="" />Scaffold</span>
      <p>Creates all files — .js, .html, .css, .stories.js, and .mdx — in one go.</p>
    </div>
    <div className="step-card">
      <span className="step-pill"><img src="/images/read-me/register.png" alt="" />Register</span>
      <p>Adds the component to .storybook/components.js so Storybook renders it instantly.</p>
    </div>
    <div className="step-card">
      <span className="step-pill"><img src="/images/read-me/style.png" alt="" />Style</span>
      <p>Applies SLDS styling rules and platform conventions automatically.</p>
    </div>
    <div className="step-card">
      <span className="step-pill"><img src="/images/read-me/document.png" alt="" />Document</span>
      <p>Generates Storybook stories with controls and full documentation.</p>
    </div>
  </div>

  <p>Components live in <code>src/modules/c/yourComponent/</code> and follow these enforced rules:</p>

  <div className="block">
    <p><strong>1.</strong> Always wrap Lightning Base Components — never recreate what lightning-* provides</p>
    <p><strong>2.</strong> Use built-in variants first — variant=&quot;success&quot; over custom CSS</p>
    <p><strong>3.</strong> SLDS styling hooks at :host — --slds-c-* custom properties</p>
    <p><strong>4.</strong> SLDS utility classes for spacing, alignment, typography</p>
    <p><strong>5.</strong> No !important, no hard-coded colors, no direct SLDS class overrides</p>
  </div>

  <h3 id="checklist">Health Check and Quality</h3>

  <p>This project includes UI Health Check skills that audit components across 8 dimensions:</p>

  <div className="block">
    <p>Accessibility (WCAG 2.1 AA) — LWC best practices — Performance — Design system compliance (SLDS2, SLDS1, WES) — JavaScript quality — Testing coverage — Storybook integration — Security</p>
  </div>

  <p>Run <code>/ui-health-check</code> for a full audit, or <code>/ui-health-fix --preview</code> to see auto-fix proposals with confidence scoring.</p>

  <h4>Claude Hooks (Automatic)</h4>

  <p>The following hooks run automatically when working with Claude Code:</p>

  <div className="block">
    <p><strong>Pre-tool:</strong> Ensures Node 20 via nvm before any shell command</p>
    <p><strong>Post-tool:</strong> Flags missing .mdx docs when component files are modified</p>
    <p><strong>Prompt:</strong> Triggers component creation procedure when relevant</p>
  </div>
</div>
